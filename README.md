작성일: 2026년 5월 30일 
작성자: 백엔드 담당


1. 현재 진행 요약
라즈베리 파이 5 환경에서 AI 모델(YAMNet)의 실시간 오디오 추론부터 FastAPI 백엔드 처리, DB 저장, 그리고 스마트폰(텔레그램) 실시간 푸시 알림까지 이어지는 End-to-End 시스템 통신 파이프라인 구축을 100% 완료했습니다.


2. 백엔드(서버) 주요 개발 완료 사항
웹소켓(WebSocket) 중계 터널 개통: 모델에서 보내온 위험 데이터를 보호자 웹 브라우저(프론트엔드)로 즉시 푸시할 수 있는 실시간 통로(ws://.../ws/alerts) 구축 완료.

Pydantic 데이터 검증(Validation) 도입: 모델에서 들어오는 JSON 데이터의 타입과 누락 여부를 서버 입구에서 자동으로 검사하여 서버 안정성 확보 (잘못된 데이터 시 422 Error 반환).

SQLite DB 연동 (히스토리 저장): 위험 알림 발생 시 alerts.db에 내역(시간, 소리 종류, 확률)을 영구 저장하고, 프론트엔드에서 과거 기록을 불러올 수 있는 조회 API(/api/history) 구현 완료.

텔레그램(Telegram) 봇 연동: 24시간 모니터링을 위해 백엔드에서 위험 신호 수신 즉시 보호자의 스마트폰으로 푸시 알림 발송 기능 연동 완료. (보안을 위해 .env 환경변수로 토큰 분리 적용)


3. AI 모델 파트 트러블슈팅 (주요 해결 이슈)
팀원분이 작성하신 훌륭한 sound_detect.py 코드 덕분에 백엔드 통신 로직(requests.post)은 한 번에 연동되었습니다.
다만, 라즈베리 파이 5 하드웨어 환경의 특수성으로 인해 발생한 3가지 크리티컬 이슈를 디버깅하여 최종 해결했습니다.

[이슈 1] USB 마이크 인식 오류 (OSError: -9996)

원인: 라즈베리 파이 내장 마이크 부재로 인한 PyAudio 장치 인식 실패.

해결: arecord -l 명령어로 USB 마이크 번호(card 2)를 찾아 코드에 명시적으로 연결 (DEVICE_INDEX=2).

[이슈 2] Sample Rate 충돌 및 배열 크기 에러 (OSError: -9997)

원인: YAMNet은 16,000Hz를 요구하나 USB 마이크 물리 스펙은 48,000Hz 고정. 강제 16kHz 녹음 시 마이크 드라이버가 뻗는 현상 발생.

해결: 마이크는 48kHz로 열고, 수집된 데이터를 파이썬(numpy.interp) 내부에서 16kHz로 실시간 선형 보간 리샘플링(압축) 하도록 로직 전면 수정 및 배열 사이즈 핏팅 버그 해결.

[이슈 3] 메모리 충돌 / Segmentation Fault (끝판왕)

원인: 라즈베리 파이 CPU에서 TFLite(AI 엔진), NumPy, PyAudio 내부 C 라이브러리 간의 코어(스레드) 쟁탈전으로 인한 OS 강제 종료 현상.

해결: 1. OS 환경변수를 통해 모든 수학 엔진의 스레드를 1개로 제한 (os.environ["OPENBLAS_NUM_THREADS"] = "1").
2. 메모리 충돌을 일으키는 무거운 scipy 제거.
3. AI 모델 추론 시 단일 코어만 사용하도록 강제 (num_threads=1).
4. (핵심) 충돌의 주범인 PyAudio 라이브러리를 완전히 버리고, 리눅스 자체 무적 녹음기인 arecord 파이프(subprocess)로 우회 연결하여 충돌 원천 차단.
